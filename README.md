## সূত্র-তালিকা

১৩টি প্রবন্ধের মধ্যে ৯টিতে «সূত্র ও আরও পড়ুন» সেকশন আছে। এতে প্রতিটি দাবির উৎস, বইয়ের নাম, সংস্করণ ও যেখানে সম্ভব অফিসিয়াল লিংক দেওয়া — পাঠক নিজে যাচাই করতে পারেন।

**নতুন প্রবন্ধ লেখার সময়** প্রবন্ধের `</article>`-এর ঠিক আগে এই কাঠামো ব্যবহার করুন:

```html
<section class="article-refs"><h2 class="article-refs-title">সূত্র ও আরও পড়ুন</h2>
<p class="article-refs-note">সংক্ষিপ্ত ব্যাখ্যা…</p>
<ol class="article-refs-list">
<li><b>লেখকের নাম</b> — <i>বইয়ের নাম</i> (প্রকাশক, সাল)। কেন ব্যবহার হয়েছে।</li>
</ol>
<p class="article-refs-warn"><b>সতর্কতা:</b> …</p>
</section>
```

CSS: `.article-refs*` — `assets/site-extra.css`-এ।

**নিয়ম:** সব বহিঃসংযোগে `rel="noopener nofollow" target="_blank"` দিতে হবে।

## sitemap

`tools/update_sitemap.py` **এবং** `tools/seo.py` — দুটোই shallow clone সনাক্ত করে `lastmod` বাদ দেয়।

> **গুরুত্বপূর্ণ:** `tools/seo.py` প্রতিবার `sitemap.xml` **নতুন করে বানায়**। তাই sitemap হাতে সম্পাদনা করবেন না — `seo.py` চালালে সেটি মুছে যাবে। shallow-সনাক্তকরণ এখন `seo.py`-তেও যোগ করা হয়েছে, তাই বানানো `lastmod` আর ফিরে আসবে না।

```bash
python3 tools/update_sitemap.py --dry-run   # কী বদলাবে দেখুন
python3 tools/update_sitemap.py             # প্রয়োগ
```

**Shallow clone-এ সতর্কতা:** যদি সব ফাইলের git-তারিখ একই হয় (স্বাভাবিক, কারণ shallow clone-এ মাত্র ১টি কমিট থাকে), স্ক্রিপ্ট **কোনো `lastmod` লেখে না** — বানানো তারিখের চেয়ে না-থাকা ভালো, কারণ Google বানানো `lastmod` উপেক্ষা করে। পূর্ণ ইতিহাস থাকলে (`git fetch --unshallow`) নিজে থেকেই সত্যিকার তারিখ বসবে।

### অফলাইন ও ইনস্টল

`sw.js` সার্ভিস-ওয়ার্কার তিন স্তরে ক্যাশ করে:

| স্তর | কী | কৌশল |
|---|---|---|
| `ead-shell-v2` | CSS · JS · ফন্ট · আইকন (২৩ ফাইল, ≈২.২ MB কাঁচা ≈০.৬ MB গজিপ) | install-এ precache → cache-first, **৩০০ এন্ট্রি / ৬ MB** |
| `ead-pages-v2` | HTML পাতা | network-first → ক্যাশ → `offline.html`, **২০০ এন্ট্রি / ২৫ MB** |
| `ead-data-v1` | হাদিস/কুরআন/গ্রন্থের JSON + `search-ayahs.js` | cache-first, **২৫০ এন্ট্রি / ৪৫ MB** |

**সীমা কীভাবে মানা হয়:** প্রতিটি ক্যাশের দুই বাজেট — এন্ট্রি-সংখ্যা আর মোট বাইট। যেটা আগে ছাড়ায়, সেই অনুযায়ী পুরোনো এন্ট্রি বাদ যায় (`trimCache` → `sizeOf`)। আকার আসে `Content-Length` থেকে; না থাকলে `blob()` করে সত্যিকারের মাপ। স্ক্যানগুলো serialized — একসাথে অনেক fetch এলে বারবার পুরো ক্যাশ স্ক্যান করে না।

**সংস্করণ:** শেল/পাতার কিছু বদলালে `SHELL_VERSION` বাড়ান — শুধু শেল-ক্যাশ বদলাবে, **ব্যবহারকারীর জমানো ডেটা অটুট থাকবে**। ডেটার JSON-গঠন বদলালে তবেই `DATA_VERSION`।

- **প্রথম খোলা:** শুধু শেল নামে (≈০.৬ MB) — ১৪৪ MB ডেটা পরে পড়ার সময় নীরবে জমে
- **কখনো ক্যাশে নয়:** অন্য ডোমেইন (`origin` যাচাই), `POST`/বাইরের রিকোয়েস্ট
- **আপডেট:** `SHELL_VERSION` বদলালে নতুন শেল-ক্যাশ; পুরোনো শেল/পাতা নিজে মুছে যায়, ডেটা থাকে
- `offline.html` — ইন্টারনেট ছাড়া খোলা হলে এটাই দেখায় (noindex, canonical নেই)

`assets/pwa.js` (প্রতিটি পাতায় `defer`):

- `/ead/sw.js` রেজিস্টার করে — শুধু `https:` বা `localhost`-এ
- **হোম-হিরোতে স্থায়ী বোতাম:** «আলোচনার বিষয়»-এর ডান পাশে তৃতীয় `.btn.ghost` — সব ব্রাউজারেই দেখা যায়; চাপলে ব্রাউজারের আসল প্রম্পট, না থাকলে (iOS/পুরোনো) ধাপে-ধাপে নির্দেশনা
- **Android/ডেস্কটপ:** `beforeinstallprompt` ধরে ৩ সেকেন্ড পর নিজের «ইনস্টল করুন» ব্যানার
- **iPhone/iPad (Safari):** ১০ সেকেন্ড পর «শেয়ার ▸ হোম স্ক্রিনে যোগ করুন» নির্দেশনা
- **আপডেট:** নতুন SW পেলে «নতুন সংস্করণ এসেছে — রিফ্রেশ» বার
- **অফলাইন:** উপরে সোনালি নোটিশ, অনলাইনে নিজে যায়
- «পরে» চাপলে ৩০ দিন আর দেখায় না; ইনস্টল হলে ১ বছর

> ⚠️ সার্ভিস-ওয়ার্কার শুধু **`https://`** বা **`localhost`**-এ চলে — ফাইল সরাসরি (`file://`) খুললে নীরবে বাদ যায়, বাকি সাইট স্বাভাবিক থাকে।

## সাইট-সার্চ

হেডারের «খুঁজুন» বোতাম, `Ctrl`/`⌘`+`K` বা `/` চাপলে পুরো সাইট-জুড়ে সার্চ খোলে। ফল আসে এক ফাইল থেকেই — কোনো সার্ভার বা fetch লাগে না, তাই `file://`-তেও কাজ করে।

- `assets/search-index.js` — মূল সূচি (≈২৭৮ KB): ২৬টি পাতা, ১১৪ সূরা, ৭ কিতাব, ৪৮ গ্রন্থ-অধ্যায়
  - **চাহিদা-মতো লোড:** বোতাম/Ctrl+K/«/» চাপলে তবেই নামে (`site-search.js`-এর `loadIndex()`)। আগে প্রতিটি পাতায় ২৭৮ KB ছাপা হত — প্রথম লোড ৪৮৮ KB → **২১১ KB**। লোডের সময় «সূচি খুলছে…» দেখায়
- `assets/search-ayahs.js` — কুরআনের **৬,২৩৬টি আয়াত** (≈২.১ MB)। প্রতিটি পাতায় লোড হয় না — সার্চ খুললে নীরবে, আর টাইপ করলে চাহিদা-ভিত্তিক নামে
- `assets/site-search.js` — মোডাল, কীবোর্ড-নেভিগেশন, হাইলাইট, ফোকাস-ট্র্যাপ, আয়াত-লোডার
- `tools/build_search_index.py` — সূচি (ও আয়াত-ফাইল) তৈরি করে
- `tools/wire_search.py` — সব পাতায় বোতাম ও স্ক্রিপ্ট বসায় (বারবার চালালেও ডুপ্লিকেট হয় না)
- `tools/test_search.mjs` — ১৮টি স্বয়ংক্রিয় পরীক্ষা (মূল সূচি)
- `tools/test_ayahs.mjs` — ১১টি পরীক্ষা (আয়াত-সার্চ, বাস্তব HTTP-তে; আগে `python3 -m http.server 8778` চালাতে হবে)

### আয়াত-সার্চ

সার্চে এখন কুরআনের **ভেতরের লেখাও** খোঁজা যায় — শুধু সূরার নাম নয়:

```
«ধৈর্য»  → ১২টি আয়াত   (সূরা ইউনুস ১০:১০৯, হূদ ১১:১১ …)
«নামাজ»  → ১২টি আয়াত   (প্রতিশব্দ: কুরআনে «সালাত»)
«জান্নাত» → ১২টি আয়াত
```

ফল সাজানো হয়: **আগে পাতা/সূরা/বই, পরে আয়াত** — যাতে আয়াতের ভিড়ে আসল পাতা হারিয়ে না যায়। ফলের সংখ্যা ২৪-এর বেশি নয়।

**প্রতিশব্দ** (`SYNONYMS`, `site-search.js`-এ): কুরআনে যেসব শব্দ নেই কিন্তু মানুষ খোঁজে — নামাজ↔সালাত, রোজা↔সিয়াম, ধৈর্য↔সবর, গুনাহ↔পাপ, দোযখ↔জাহান্নাম ইত্যাদি।

**এইচটিএমএল বদলালে:**

```bash
python3 tools/build_search_index.py   # সূচি নতুন করে বানায়
python3 tools/wire_search.py          # নতুন পাতা থাকলে তার সঙ্গে যুক্ত করে
node tools/test_search.mjs            # যাচাই
```

বাংলা বানান-ভিন্নতাও মেলে — `ি`/`ী`, `ু`/`ূ`, `য়`/`য`, নুকতা ও `ৎ` সার্চে সমান ধরা হয় (যেমন «ইয়াসিন» লিখলেও «সূরা ইয়াসীন» পাওয়া যায়)।

## হোস্টিং
ZIP extract করে `ebrahim-ead-website/` ফোল্ডারের সব HTML, `assets/` ও `files/` একসঙ্গে হোস্ট করুন। `index.html` হলো হোমপেজ। এই ZIP-এ build source নেই; source ও data workspace-এ আলাদাভাবে আছে।

- `bible-science-analysis.html` — বাইবেলের বক্তব্য ও বিজ্ঞান বিষয়ক পূর্ণ প্রবন্ধ; ছোট ছবিসহ।

- `jesus-bible-quran.html` — যীশু সম্পর্কে বাইবেল ও কুরআনের তুলনামূলক প্রবন্ধ, আরবি উদ্ধৃতি ও সূত্রসহ; ছবি নেই।
